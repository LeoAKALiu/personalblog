# 项目介绍

## 项目定位

`personalblog` 是一个基于 Next.js 构建的个人网站项目，用于系统展示个人在城市体检、工程智能化与 AI 落地方向的经验、能力、成果与合作方式。

这个项目的目标不是做一个泛展示型博客，而是做一个兼顾以下场景的专业主页：

- 对外展示个人专业身份与长期研究方向
- 帮助潜在合作方快速理解可提供的能力与价值
- 作为咨询、项目合作、培训交流的入口页
- 为后续品牌化改版、UI 二次设计和内容扩展提供稳定基础

从信息结构上看，它更接近“个人品牌官网 + 专业能力主页”，而不是传统按时间线更新内容的博客系统。

## 当前技术栈

项目当前采用的核心技术如下：

- `Next.js 16`：使用 App Router 目录结构
- `React + TypeScript`：用于组件开发与类型约束
- `Tailwind CSS`：负责页面布局、颜色、间距与响应式样式
- `Lucide React`：用于图标展示
- `Docker`：用于生产环境构建与运行
- `Nginx Proxy Manager`：用于反向代理、HTTPS 证书与域名入口管理

项目通过 `Dockerfile` 与 `docker-compose.yml` 支持容器化部署，生产环境中的应用容器名为 `portfolio-web`。

## 目录结构说明

下面是当前项目中最值得关注的目录和文件。

### `app/`

这是 Next.js App Router 的入口目录。

- `app/layout.tsx`
  - 定义全局页面结构
  - 一般放置主题、字体、全局布局容器、公共组件入口
- `app/page.tsx`
  - 首页主文件
  - 负责组织 Hero、行业痛点、核心能力、合作方式、职业经历、学术成果等模块
- `app/projects/page.tsx`
  - 项目 / 解决方案展示页
- `app/api/health/route.ts`
  - 健康检查接口
  - 可用于 Docker healthcheck、反向代理探活与运维排查
- `app/globals.css`
  - 全局样式定义
  - 包括 Tailwind 基础样式和站点级样式规则

### `components/`

这是项目的 UI 组件层，承载了页面中的大部分结构与交互。

常见组件包括：

- `Header.tsx`：顶部导航
- `SideNav.tsx`：首页左侧分区导航
- `PainPoints.tsx`：行业问题 / 痛点模块
- `CapabilitiesNew.tsx`：核心能力模块
- `CooperationModes.tsx`：合作方式模块
- `CardList.tsx`：通用卡片列表容器
- `InfoCard.tsx`：信息卡片
- `ProjectCard.tsx`：项目展示卡片
- `ContactFAB.tsx`：悬浮联系入口，包含邮箱、电话、微信二维码
- `FadeInOnScroll.tsx`：滚动进入动画
- `ScrollToTop.tsx`：回到顶部按钮
- `Footer.tsx`：页脚

### `data/`

该目录存放结构化数据，当前最核心的是：

- `data/resume.ts`
  - 包含个人信息
  - 工作经历
  - 项目经历
  - 学术成果
  - 其他展示型数据

这个目录的设计思路是“数据驱动页面”，即页面组件尽量只负责渲染与布局，内容则从数据文件读取。

### `public/`

该目录用于放置静态资源，例如：

- 社交分享图

## 页面结构说明

当前首页由以下几类信息模块组成。

### 1. Hero 首屏

首页首屏强调身份、方向与合作入口，通常包含：

- 一句核心定位文案
- 一段补充说明
- 三行问题摘要或方法论摘要
- 若干高亮标签 / credential 标签
- CTA 按钮，例如查看案例、预约沟通

这一部分承担“用户进入页面后 5 秒内建立印象”的任务。

### 2. 行业痛点模块

通过 `PainPoints` 组件展示行业中的关键问题，例如：

- 传统检测方式难以沉淀为可决策的数据
- AI 模型在真实工程场景中难以落地
- 物理机理与数据模型之间缺少有效融合

这一模块的作用是先讲“问题”，再引出后续的能力与方案。

### 3. 核心能力模块

由 `CapabilitiesNew` 负责展示，可以理解为“我能做什么”。

通常包括：

- 能力分类
- 能力卡片
- 面向客户或合作方可理解的简要描述

它是整个站点中非常重要的中段模块，决定了访客能否迅速建立能力认知。

### 4. 合作方式模块

由 `CooperationModes` 展示。

主要作用：

- 让访问者理解可以如何开展合作
- 降低从“感兴趣”到“发起联系”的阻力
- 让站点从展示页转化为沟通入口

### 5. 职业经历模块

在首页中以时间轴或分段展示形式呈现，当前实现位于 `app/page.tsx`。

特点：

- 使用 `resumeData.experience` 作为数据源
- 支持条目折叠与展开
- 更偏向专业成长与项目经历的结构化呈现

### 6. 学术成果模块

通过 `CardList` 统一展示论文、专利等成果。

作用：

- 提供学术与研究方向的背书
- 强化专业可信度
- 补充产业实践之外的成果面

## 组件与数据的协作方式

项目目前整体采用的是一种比较清晰的“数据驱动 + 组件渲染”方式：

1. 在 `data/` 中组织结构化内容
2. 在页面中通过组件消费数据
3. 组件负责视觉呈现和局部交互
4. 首页负责整体编排与叙事顺序

这样做的好处是：

- 改内容时不用深入改布局逻辑
- 改样式时不必频繁修改数据结构
- 适合持续迭代与 AI 协作开发
- 很适合后续做 UI 二次设计

## 当前项目的运行方式

### 本地开发

如果在本地安装了 Node.js 20+，可以直接运行：

```bash
npm install
npm run dev
```

默认访问：

```text
http://localhost:3000
```

### 生产构建

```bash
npm run build
npm run start
```

### Docker 运行

```bash
docker compose build
docker compose up -d
```

健康检查接口：

```text
/api/health
```

## 项目的设计价值

这个项目最有价值的地方，不只是“已经能展示内容”，而是它已经具备了进一步品牌化改版的结构基础：

- 内容区块清晰
- 模块边界明确
- 页面结构适合继续拆分和重组
- 组件命名直观，适合设计与开发协作
- 静态资源与结构化数据已经分离

这意味着它非常适合作为一套“可迭代的个人品牌站点系统”继续发展。

## 适合后续优化的方向

基于当前结构，后续可以考虑的方向包括：

- 重做首页视觉体系，提高品牌识别度
- 统一卡片系统与视觉 token
- 把项目页做成更完整的案例页体系
- 增加专题内容页或文章页
- 梳理更完整的移动端交互细节
- 增加更明确的转化路径设计

如果后续要用 Pencil、Figma 或其他设计工具进行改版，这个项目现有结构已经足够作为设计落地的开发底座。
