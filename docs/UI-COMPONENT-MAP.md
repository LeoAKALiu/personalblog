# UI 视角组件地图

## 文档目的

这份文档从 UI / 页面设计角度介绍当前项目，重点不是技术实现细节，而是帮助你快速理解：

- 页面由哪些视觉模块构成
- 每个模块对应哪些代码文件
- 哪些位置最适合做界面改版
- 哪些组件是公共样式入口
- 如果要用 Pencil 做二次设计，应该优先改哪里

如果把 `PROJECT-OVERVIEW.md` 看作项目总览，那么这份文档更像“设计师与前端协作地图”。

## 页面层级总览

当前站点可以分为两个主要页面：

- 首页：`app/page.tsx`
- 项目页：`app/projects/page.tsx`

从 UI 角度看，首页是主叙事页面，项目页是补充展示页面。

首页承担的任务包括：

- 建立个人品牌印象
- 解释行业问题
- 展示核心能力
- 说明合作方式
- 展示职业与学术背书
- 提供明确联系入口

## 首页视觉结构

首页目前可以理解为“纵向叙事型 landing page”，主要由以下几块组成。

### 1. 左侧分区导航

对应文件：

- `components/SideNav.tsx`

作用：

- 在桌面端显示当前页面的章节导航
- 根据滚动位置高亮当前 section
- 提供快速跳转

设计关注点：

- 当前视觉上偏功能性
- 可以进一步强化层级、品牌感和滚动反馈
- 若想做更强的 editorial 风格，这里是很好的切入口

### 2. 顶部导航

对应文件：

- `components/Header.tsx`
- `components/Navbar.tsx`

作用：

- 提供首页与项目页的主导航
- 兼顾移动端菜单
- 承担品牌入口和主题切换入口

设计关注点：

- 顶部导航的高度、透明度、滚动状态、响应式折叠方式都可以优化
- 可重新定义 Logo、菜单权重、CTA 的视觉优先级

### 3. Hero 首屏

对应文件：

- `app/page.tsx`

视觉组成：

- 状态徽章
- 主标题
- 副标题
- 三条摘要信息
- credential 标签
- 两个 CTA 按钮

作用：

- 这是全站最关键的第一屏
- 决定“第一印象是否专业、可信、有记忆点”

设计建议：

- 优先重做这一屏的版式和视觉主次
- 可以尝试更鲜明的标题结构、更明确的视觉锚点
- 也可以为摘要信息设计更强的模块节奏

### 4. 行业痛点模块

对应文件：

- `components/PainPoints.tsx`

作用：

- 告诉用户“为什么这个人 / 这套能力值得继续看”
- 构建问题背景和行业 context

UI 设计关注点：

- 该模块容易做成单调列表
- 更适合通过层级、对比、留白、图标或数字来增强阅读节奏
- 如果做品牌升级，这一块很适合建立“问题陈述”的视觉语言

### 5. 核心能力模块

对应文件：

- `components/CapabilitiesNew.tsx`
- `components/commercial/CapabilitiesMatrix.tsx`

作用：

- 说明“我能解决什么问题”
- 将抽象能力拆解为访客易理解的结构

UI 设计关注点：

- 这是最适合做“体系化设计”的模块之一
- 可以通过卡片系统、矩阵布局、标签体系或分栏排版来强化专业感
- 如果要提升商业化表达，这里值得重点设计

### 6. 合作方式模块

对应文件：

- `components/CooperationModes.tsx`

作用：

- 把展示页转成可沟通的入口页
- 告诉潜在合作方“可以怎么合作”

UI 设计关注点：

- 适合做成一组可比较的合作卡片
- 可以增加合作节奏、交付形式、参与方式等信息层级
- 如果想提升转化感，这里值得加入更明确的 CTA 逻辑

### 7. 职业经历模块

对应文件：

- `app/page.tsx`

内部关键实现：

- `ExperienceItem`

当前表现方式：

- 时间轴结构
- 支持展开 / 收起更多经历描述

UI 设计关注点：

- 时间轴是目前这一块最强的结构特征
- 可继续优化节点、线条、时间标签、折叠交互的视觉表现
- 如果想做更高级的视觉叙事，可以围绕“时间 / 阶段 / 能力演进”来重构

### 8. 学术成果模块

对应文件：

- `app/page.tsx`
- `components/CardList.tsx`

作用：

- 提供成果背书
- 统一显示论文与专利

UI 设计关注点：

- 容易做得偏“信息堆叠”
- 更适合建立统一的成果卡片样式
- 需要平衡“学术感”和“易读性”

### 9. 联系方式浮动按钮

对应文件：

- `components/ContactFAB.tsx`

作用：

- 保持全局可触达的联系入口
- 展开后显示邮箱、电话、微信二维码

UI 设计关注点：

- 这是转化功能组件
- 适合强化按钮辨识度、面板层次与打开动画
- 也可以考虑把它做得更轻，避免压住页面内容

### 10. 页脚与辅助交互

对应文件：

- `components/Footer.tsx`
- `components/ScrollToTop.tsx`

作用：

- 补足页面闭环
- 提供辅助导航和结束信息

UI 设计关注点：

- 页脚可做成品牌补充区
- 回到顶部按钮可以统一进浮动操作系统里

## 组件角色分类

从设计与开发协作角度，可以把组件分成四类。

### 一类：页面骨架组件

这些组件决定页面的大框架和导航行为。

- `Header.tsx`
- `SideNav.tsx`
- `Footer.tsx`
- `Navbar.tsx`
- `app/layout.tsx`
- `app/page.tsx`

适合改什么：

- 站点整体布局
- 导航结构
- 页面留白
- 头尾关系
- 全局层级

### 二类：内容表达组件

这些组件承载站点的主要信息内容。

- `PainPoints.tsx`
- `CapabilitiesNew.tsx`
- `CooperationModes.tsx`
- `ProjectCard.tsx`
- `InfoCard.tsx`
- `CardList.tsx`

适合改什么：

- 卡片系统
- 信息层级
- 网格布局
- 模块标题样式
- 内容块之间的视觉节奏

### 三类：交互增强组件

这些组件提供行为层与动效层。

- `FadeInOnScroll.tsx`
- `ScrollToTop.tsx`
- `ContactFAB.tsx`
- `mode-toggle.tsx`

适合改什么：

- 出场动画
- hover / active 状态
- 浮层展开方式
- 交互反馈细节

### 四类：品牌与基础元素组件

这些组件属于品牌识别和基础视觉构件。

- `LogoMark.tsx`
- `theme-provider.tsx`
- `components/ui/` 下的基础组件

适合改什么：

- Logo 使用方式
- 主题切换体验
- 统一按钮、边框、圆角、阴影风格

## 适合 UI 改版的优先级建议

如果你准备先在 Pencil 里做二次设计，推荐按下面顺序推进。

### 第一优先级：首屏与导航系统

原因：

- 改动收益最大
- 直接影响品牌第一印象
- 能最快决定整个站点的设计基调

优先关注文件：

- `app/page.tsx`
- `components/Header.tsx`
- `components/SideNav.tsx`
- `components/LogoMark.tsx`

### 第二优先级：核心能力 + 合作方式

原因：

- 这是最接近业务转化的区域
- 结构清晰，最适合做视觉体系升级

优先关注文件：

- `components/CapabilitiesNew.tsx`
- `components/CooperationModes.tsx`
- `components/commercial/CapabilitiesMatrix.tsx`

### 第三优先级：通用卡片系统

原因：

- 一旦卡片系统统一，整站视觉会稳定很多
- 对项目页和成果页都有正向影响

优先关注文件：

- `components/CardList.tsx`
- `components/InfoCard.tsx`
- `components/ProjectCard.tsx`

### 第四优先级：联系入口与细节体验

原因：

- 属于锦上添花
- 更适合在整体视觉确定后做统一优化

优先关注文件：

- `components/ContactFAB.tsx`
- `components/ScrollToTop.tsx`
- `components/Footer.tsx`

## 当前 UI 风格特点

当前站点整体风格有这些明显特征：

- 使用 Tailwind 工具类直接构建界面
- 配色偏克制、理性、专业
- 模块分段清晰
- 内容密度中等偏高
- 比较重视响应式与可读性
- 有基础动效，但整体仍以信息表达为主

这说明它已经具备“稳定、清楚”的基础，但仍有较大空间往更强的品牌化、作品集化方向升级。

## 从 Pencil 到代码的落地建议

如果你在 Pencil 里做设计，建议用以下方式映射到现有代码。

### 方式一：按页面区块画

直接对应首页的 section：

1. Hero
2. PainPoints
3. Capabilities
4. Cooperation
5. Experience
6. Academic
7. Footer / FAB

好处：

- 最接近最终页面
- 便于你先确定模块顺序与页面叙事节奏

### 方式二：按组件系统画

先抽象几个基础 UI 模板：

- 模块标题样式
- 卡片样式
- 标签样式
- 主按钮 / 次按钮
- 时间轴条目
- 悬浮面板

好处：

- 更适合系统化设计
- 后续前端实现效率更高

### 方式三：先做首页，再反推项目页

推荐原因：

- 首页决定整个站点的设计语言
- 项目页可沿用首页确定下来的卡片、标题和版式系统

## 适合进一步沉淀成设计规范的部分

如果这次二次设计希望更系统，建议最后把下面几类内容固化下来：

- 标题层级规则
- 模块间距规则
- 卡片边框 / 阴影 / 圆角规则
- CTA 按钮体系
- 标签与徽章体系
- 图片比例和裁切规则
- 桌面端 / 平板 / 手机端断点表现

一旦这些规则固定，后续新增页面和内容时就不容易“越改越乱”。

## 总结

从 UI 视角看，这个项目最大的优势不是“现成界面多么完整”，而是：

- 信息结构已经清楚
- 模块边界已经明确
- 首页叙事已经形成
- 组件拆分已经具备继续设计的基础

这意味着你完全可以先在 Pencil 中大胆做视觉与版式升级，再回到现有项目中按组件逐步落地，而不需要推翻整个站点重做。
