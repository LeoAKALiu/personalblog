# 本机资源检查与配置建议

基于当前单机（运行 personalblog + Nginx + Harbor 等）的检查结果与建议。

---

## 当前资源概况

| 资源 | 当前 | 状态 |
|------|------|------|
| **CPU** | 2 核，负载 ~0.01–0.08 | 充足 |
| **内存** | 3.5 GiB 总量，约 1.4 GiB 可用，Swap 2 GiB（已用约 88 MiB） | 尚可，需留意 |
| **磁盘** | 根分区 40G，已用约 97%（约 1.4G 可用） | **紧张，建议尽快处理** |
| **容器** | portfolio-web 约 60 MiB / 1.5 GiB 上限，其余 13 个容器合计占用适中 | 正常 |

---

## 1. 磁盘（优先处理）

- **现象**：`/` 使用率约 **97%**，仅约 1.4G 可用，写满会导致服务异常或崩溃。
- **可立即回收**：
  - Docker **构建缓存**约 **13.35 GB** 可清理；
  - 未使用镜像约 **1 GB** 可回收。
- **建议操作**（在服务器上执行）：
  ```bash
  # 只清构建缓存（不动镜像/容器），通常可腾出约 13 GB
  docker builder prune -af

  # 若还需再腾空间：清理未使用的镜像、网络、容器
  docker system prune -af
  ```
  `docker system prune -af` 会删除未使用的镜像，若当前没有其他项目依赖这些镜像，可执行；否则优先只做 `docker builder prune -af`。
- **中长期**：若 40G 仍不够（日志、数据、多项目），建议扩容根盘或挂载新数据盘并迁移 Docker 数据目录。

---

## 2. 内存

- **当前**：约 1.4 GiB 可用，多容器共存（Harbor、Nginx、Redis、portfolio-web 等），平时够用。
- **风险**：构建镜像或高并发时内存会升高，可用会减少。
- **建议**：维持现状即可；若后续增加服务或构建频繁，建议升级到 **4～8 GiB** 更稳。

---

## 3. CPU

- **当前**：2 核，负载很低，对当前业务足够。
- **建议**：无需为 personalblog 单独升级；若同一台机要跑更多服务或做 CI 构建，可考虑 **4 核**。

---

## 4. 新机/新配置推荐

若要新购或重装一台只跑 **liubo.xin（personalblog + 反代）** 的机器，推荐最低与建议配置如下。

| 项目 | 最低配置 | 建议配置 |
|------|----------|----------|
| **CPU** | 2 核 | 2 核（若同时跑 Harbor/CI 可 4 核） |
| **内存** | 2 GiB | 4 GiB |
| **系统盘** | 40 GiB | **60 GiB 及以上**（避免再次出现 97% 占满） |
| **系统** | Linux（AlmaLinux/Ubuntu 等） | 同左 |
| **网络** | 公网 IP，开放 80/443 | 同左 |

若新机同时跑 **Nginx Proxy Manager + personalblog + 其他少量容器**，建议：**2 核 / 4 GiB / 60G 系统盘**，并定期清理 Docker 构建缓存（如 cron 每周 `docker builder prune -f`）。

---

## 5. 增配建议（当前机器可这样加）

在现有 2 核 / 3.5 GiB / 40G 盘基础上，按优先级建议：

| 优先级 | 资源 | 当前 | 建议增配后 | 说明 |
|--------|------|------|------------|------|
| **1（必选）** | **系统盘** | 40G，约 97% 满 | **60G 或 80G** | 避免再次写满导致宕机；云上可在控制台「扩容云盘」后扩展分区与文件系统。 |
| 2（可选） | 内存 | 3.5 GiB | **4～6 GiB** | 多容器 + 构建时更稳，不易 OOM。 |
| 3（可选） | CPU | 2 核 | 2 核或 **4 核** | 当前负载低，可不加；若常做镜像构建或再挂其他服务，可加到 4 核。 |

**操作顺序建议**：先做磁盘扩容（或先执行 `docker builder prune -af` 临时腾空间），再视预算加内存；CPU 一般可先不动。

---

## 6. 定期维护建议

- **每周或每月**：`docker builder prune -f`，避免构建缓存占满磁盘。
- **监控**：对根分区做告警（例如使用率 &gt; 85% 告警），便于提前扩容或清理。
- **日志**：为 Nginx / Docker 配置日志轮转与大小上限，避免日志写满磁盘。
